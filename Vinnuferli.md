### Rýni (Peer Review) og Git vinnuferli
* **Einstaklingsvinna & Rýni:** Við unnum okkar hluta sjálfstætt, en yfirfórum og rýndum texta og kröfur hjá hvor öðrum áður en lokagerðin var staðfest.
Allar breytingar og textavinna voru framkvæmdar beint í gegnum GitHub vefviðmótið til að halda vinnuferlinu gegnsæju:

1. **Issues & Branches:** Búið var til **Issue** á GitHub fyrir hvern verkpakka. Ut frá því var búin til sérstök grein (branch) á GitHub vefnum.
2. **Textavinna & Commits:** Unnið var í viðkomandi skjali beint á vefnum og breytingar vistaðar með hnitmiðuðum skilaboðum (`commit`).
3. **Pull Request (PR):** Þegar vinna við Issue var tilbúin var stofnuð **Pull Request** á GitHub.
4. **Rýni (Code Review) & Merge:** Hópfélaginn yfirfór og rýndi breytingarnar í PR-inu. Að rýni lokinni var PR samþykkt og sameinað (`merged`) yfir á `main` greinina.

## Ígrundun
Að nota vefviðmót GitHub (Issues, PRs og Code Review) gerði allt vinnuflæðið mjög sýnilegt og auðvelt var að fylgjast með framgangi hvor annars.
Með því að skipta kröfugerðinni í tvo stóra hluta gátum við unnið sína vinnuna hvort í sínu lagi án þess að skara á vinnu hins.
Hugmyndin um *Vaktina* reyndist raunhæf og auðveld í greiningu, sem gerði vinnu við SRS og SDS skjölin skýra og markvissa.

### Hvað má bæta næst
* **Meiri samskipti á meðan á vinnslu stóð:** Þó að rýni á Pull Requests hafi gengið vel hefðum við mátt samstilla hugtakanotkun milli SRS/SDS skjalsins og virknikrafnanna enn fyrr í ferlinu.
